# Infrastructure, plugins, and supporting-service review

Reviewed local SDK main at `ff224741c251cae7673c5f835dcf3bbccd9d6605`, then applied the corrections below. Source comparison uses the pinned repositories and API document in `sources.json`. These are correctness and reliability findings; this review does not classify them all as exploitable security vulnerabilities.

The [I01–I11 source recheck](recheck/infrastructure.md) supersedes reachability/impact claims in this initial summary. It narrows custom-option and Pyth fee cases, labels the EVC-only entry as a duplicate, and retracts any ordinary failed-batch credential-payment implication.

## Corrections

| Area | Trigger and prior consequence | Correction and evidence |
| --- | --- | --- |
| Query cache race | A slow in-flight query outlives its TTL. A newer query finishes first, but the older response subsequently overwrites it, making subsequent callers receive older state. | Cache writes now require that the completing promise still owns its entry. A controlled completion-order regression failed on main and passes locally. |
| Request batching | At zero debounce and exhausted concurrency, the dispatch loop continually queues microtasks, preventing the I/O needed to free capacity. A synchronous batch callback exception could also strand its callers. | Dispatch resumes when capacity is freed; callback invocation is wrapped in the rejection path. Tests exercise actual queuing and synchronous failure recovery. |
| Batch options | Zero/fractional/NaN batch sizes can prevent progress. The aggregate-result helper accepts finite chunks although it cannot combine arbitrary chunk results and returns only the first. rEUL's zero batch size also never advances. | Invalid progress parameters fail early; the aggregate helper rejects finite chunking; rEUL validates before RPC. These internal utility/API edge cases are distinguished from the default configuration. |
| Read-time oracle enrichment | EVC `batchSimulation` continues after failed calls. The SDK accepted a successful lens read even if its preceding update failed or results were missing. | Every prepend and the expected lens response must succeed, with an exact result count. The onchain adapters report/fallback on enrichment failure; see data review. No transaction-validity guarantee is inferred from this read helper. |
| EVC-only Pyth preparation | A controller/collateral-only EVC operation can schedule an account check even without a vault operation. | Pyth supplies the configured EVC address to the corrected health-check discovery. An integration test verifies actual update insertion. This is the same underlying discovery finding as the execution report, not a second bug count. |
| Pyth fee query keys | `[blob]` and `[blob, blob]` were collapsed to the same cache key despite different call arguments. | Fee keys retain the full byte-array input. A provider-backed regression confirms both distinct calls are made. The test establishes cache correspondence, not a universal formula for every Pyth deployment's fee. |
| Keyring failures and credential identity | Prefetch read failures were cached as “not gated”; credential read/callback/encoding exceptions were swallowed. A callback's credential for another account, chain, or policy could be inserted into the plan. | These failures propagate as plugin errors; credentials must match the request and numeric fields must be safely representable. An explicit `null` callback remains an intentional opt-out. Seven failure variants regress the original behavior. This does not bypass onchain credential enforcement. A later batch revert also rolls back credential insertion/value transfers; no successful irrelevant-credential payment was demonstrated. |
| V3 disabled mode | `disableV3` still left built-in USD pricing, tokenlist and intrinsic APY using V3, contrary to its documented scope. | Pricing uses its onchain fallback; the other two built-ins report unavailable without HTTP. Explicit service overrides and custom tokenlist URL functions/templates remain supported; an API-base URL alone still selects the built-in V3 endpoint. The configuration regression checks no fetch occurs. |
| Refreshed enrichment | Refreshing an object with no new intrinsic APY or labels left its old value attached. A mixed-chain label population call used the first chain for every vault. | Missing values clear old enrichment and labels are grouped by chain. Regression uses the same vault address on two chains and a later empty refresh. |
| Wallet balance diagnostics | Upstream `UtilsLens.tokenBalances` catches a reverting token `balanceOf` and returns zero. The SDK regarded this indistinguishably as a successful zero read. | Zero lens responses are verified with direct `balanceOf`; a true zero stays clean, a failed read carries a diagnostic. This costs an extra balance read for zero-valued tokens. |
| Fallback error handling | `throw undefined` was treated as no failure, and the documented callback was never invoked if the secondary source also failed. | A separate rejection flag and a `finally` notification preserve error handling and observability. The secondary error still propagates and telemetry exceptions remain isolated. |

The root regressions are in `integrationInfraRegression.test.ts`, `pluginIntegrationRegression.test.ts`, and additions to `pythPlugin.test.ts`, `keyringPlugin.test.ts`, and `sdkConfig.test.ts`. Three selected infrastructure regressions and thirteen plugin/configuration regression cases were run against original main source and failed before restoration of the fixes. Other new cases were validated directly against corrected behavior and inspected original control flow; no universal claim of a recorded red run is made for every case.

## Other inspected boundaries

- SDK assembly/configuration: service overrides, fallback wiring, plugin wiring, API keys, environment precedence, and disabled services. Explicit custom sources, endpoints, callbacks and deployment maps remain trust inputs.
- Activity: API schema, cursor/filter binding, owner/subaccount/chain validation, coverage semantics, liquidation units, time and amount parsing, and bounded HTTP responses. The existing activity tests cover malformed and mismatched responses; no new confirmed defect was established in this pass.
- Wallet/rEUL: token and Permit2 allowance ABI widths, native handling, lock timestamp and remainder-loss encoding against `UtilsLens.sol` and `ERC20WrapperLocked.sol`. Locking remains enforced by the contract and reads can become stale.
- Fee flow: controller/util ABI and price/deadline/payment-cap semantics against `FeeFlowControllerEVK.sol` and `FeeFlowControllerUtil.sol`. SDK buy-plan construction remains disabled because the contract interface lacks the required atomic minimum payout protection.
- Safe: singleton/owner/threshold checks, transport versus contract failure classification and cached detection. The result is a best-effort probe, not a code-hash attestation: a contract can imitate view responses, versions/deployments vary, and owners can change during the cache TTL.
- Shared infrastructure: block pin forwarding and cache separation, read aggregation, dynamic ABI loading/retry, deployment configuration, error decoding and data diagnostics. Generated/static selector data and exported types received interface/call-site review; they were not each independently proved or matched to every deployed binary.

## Boundaries and compatibility changes

The public SDK still accepts trusted application configuration and user-supplied plugins. This review does not prove arbitrary callbacks, hostile RPC/API data, token implementations, proxy upgrades, or all deployment metadata correct. Source inspection and passing mocks do not demonstrate live deployment equivalence.

Errors that were previously swallowed now stop preparation. Unsupported batching options are rejected instead of hanging or silently dropping results. Disabled-V3 tokenlist/intrinsic APY users must handle unavailability or provide another service. Existing cached Safe/ABI/deployment data and prepared oracle data still have their documented freshness limitations. Label metadata is advisory; it does not establish onchain permissions.
