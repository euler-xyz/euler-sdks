# SDK issues ranked by production priority

This is a remediation ranking of the **reviewed original SDK main `ff224741c251cae7673c5f835dcf3bbccd9d6605`**, not a report of observed production incidents or an assertion that the published package contains exactly this code. Production consequences below apply if that code is deployed and the stated trigger occurs. Ranking weighs user impact, reachability, and existing contract safeguards; it is an engineering judgment rather than a CVSS score.

The 50 prior entries become **48 ranked groups**: E08/D01 overlap and E09/I05 are the same dependency finding. Every prior ID appears exactly once below. References lead to the detailed source recheck, including original code paths and upstream contracts.

- **P1 / high:** address before relying on transaction intent or account-risk presentation.
- **P2 / medium:** important transaction, data, or availability defects; conditional severe cases are labeled.
- **P3 / lower:** defensive validation, unusual/custom configurations, compatibility and observability.

No P0 emergency or unconditional fund-drain exploit was established. A reverted transaction generally preserves the assets moved within it, but can still cost gas; earlier separate transactions are not undone. Wrong displayed debt can mislead decisions even though the contract still enforces real debt and health.

“Local fix” means the demonstrated mechanism has an uncommitted correction and regression evidence. It does not mean production has changed, all surrounding cases are solved, or the source matches every deployment. Nothing has been pushed. **E11 approval resolution and E07 mint estimation remain partial; finish E11 first, then E07.** Earn's fee-incomplete snapshot conversions also remain a known limitation even though exact-asset planning is corrected.

## Remaining limits relevant to production

The table ranks every reported finding. The following are broader limits already recorded in the review, not additional proved vulnerabilities:

- Synthetic simulation balances/approvals do not establish actual wallet funding or authorization. Wallet diagnostic read failures can still leave checks unavailable; successful simulation is conditional.
- Missing account controller metadata, indexer coverage/lag and unavailable prices can leave risk/NAV incomplete. A fallback result is not automatically complete.
- Morpho stored totals omit pending interest; Earn snapshots omit pending fee shares. Quote freshness and subsequent state changes still matter.
- CoW order submission is not settlement; concurrent orders can contend for nonce/state. Standing migration authorizations need the application's intended revocation policy.
- Securitize enumeration remains unsupported; its existing factory accessor is hardcoded without a general chain mapping. Do not infer verified cross-chain discovery from that accessor.
- Deployment addresses/bytecode, upgrades, custom hooks/tokens and every production-chain path were not exhaustively verified. These boundaries are in the [full recheck](FINDINGS.md) and [original scope report](../REVIEW.md).

No production source was changed for this prioritization step. The prior validation remains 1,277 passing SDK tests, successful build/typecheck, and four actual-EVC Solidity tests; no claim is made that a priority ranking is itself a correctness proof.
