# Swap, migration, and CoW integration review

Reviewed SDK baseline `ff22474` plus the local corrections below. No commits or pushes were made. This is a source review and a set of executable regressions, not a proof of all SDK behavior or of deployed contract equivalence. The coverage JSON lists the SDK source files inspected; generated ABIs and barrel exports received interface/export checks, not independent bytecode verification.

An independent [S01–S10 recheck](recheck/swap-rewards.md) records exact baseline/upstream evidence, practical triggers, downstream safeguards and test limits. Its qualifications supersede broader readings of the finding summaries below.

## Confirmed corrections

| Issue | Previous behavior and consequence | Local correction and regression |
| --- | --- | --- |
| Morpho debt conversion omitted virtual shares/assets | With 500,001 borrow shares, totalBorrowAssets=2 and totalBorrowShares=1,000,000 the SDK reported 2 assets instead of the contract's 1. Conversely a nonzero share balance with zero stored assets can still owe 1 asset. These estimates feed migration borrowing/buffers. | `connectors/morpho/morphoConnector.ts` now uses ceiling(shares × (assets + 1) / (totalShares + 1,000,000)), matching upstream SharesMathLib. Five independent vectors include dust and large amounts. |
| Aave zero stable-debt token compatibility hardening | The position reader always called `balanceOf` on the stable-debt-token address. A Pool actually returning address(0) would therefore fail its multicall even when its variable-debt position was valid. | `connectors/aave/aaveConnector.ts` omits that call for zero/absent stable tokens and keeps the existing nonzero-token path. Regression covers both. The SDK calls Pool.getReserveData, whose pinned implementation uses a configured backwards-compatibility mock; it does not call the DataProvider method that always returns zero. A failing live Pool configuration was not established. |
| Caller-supplied migration position was not bound to its request | A cached position from a different owner, chain, or connector could pass into validation/building, mixing its snapshot with a new request's chain and owner. | `positionMigrationService.ts` checks all three identities before authorization, simulation planning, or batch construction. Regression supplies each mismatch through each of those three public entry points and confirms no connector action occurs. |
| Missing swapper configuration silently disabled quote allowlisting | `fetchSwapQuotes` skipped the swapper allowlist when deployment addresses were missing or all zero. It could return a quote with an arbitrary swapper. The exported allowlist helper is opt-in and is not called by ordinary SDK planners. A correctly configured verifier still enforces final output/debt conditions. No fund-loss demonstration or deployed trigger was established. | `swapService.ts` fails closed for an empty canonical allowlist. Regression rejects absent and zero deployment swappers and accepts the configured canonical swapper. |
| Zero configured verifier was accepted as trusted | Comparing a quote against a configured zero address could succeed, even though zero is not a usable verifier deployment. Static EVC source uses a low-level call without a target-code check, so a zero target does not enforce the verifier's predicates. This is conditional unsafe configuration acceptance, not a demonstrated fund-loss incident. | `swapAllowlist.ts` and `swapService.ts` reject a zero configured verifier. Regression exercises both the shared guard and fetched quote path. |
| CoW plan validation occurred after earlier effects | The executor checked each item's outer chain only as it reached that item. A valid cancellation followed by an invalid-chain item first read the nonce and sent the cancellation, then rejected the plan. Nested parameter chain and plan owner were not preflight-bound either. | `cowExecutor.ts` preflights every outer chain, parameter chain, and owner against the execution account before any read, approval, cancellation, signature, or order submission. Regression starts with a valid cancellation, appends each invalid variant, and asserts zero reads/sends. |

## Source comparison

Pinned upstream checkouts used for this review:

- EVK periphery [`816c5943e5fab3a213e907dd5beaf9542305593a`](https://github.com/euler-xyz/evk-periphery/tree/816c5943e5fab3a213e907dd5beaf9542305593a): `src/Swaps/SwapVerifier.sol`, `src/Swaps/MigrationHelper.sol`, `test/Swaps/MigrationHelperFork.t.sol`. Verifier methods enforce final token/debt minima or maxima and deadlines; `transferBalanceFromSender` transfers the lesser of the current balance and its cap. MigrationHelper derives its sender through EVC authentication. Its standing-authorization warning still applies to application cleanup policy.
- EVC [`838e5f72eaea25fab7d242760245244226096054`](https://github.com/euler-xyz/ethereum-vault-connector/tree/838e5f72eaea25fab7d242760245244226096054): `src/EthereumVaultConnector.sol`, especially `getNonce`, `setNonce`, `permit`, `batch`, and simulation. CoW EVC permit typed fields and cancellation are tied to the signer prefix and nonce namespace. - Aave V3 Origin [`8305565ae342f1773c42cd2e4593f175fe5968a0`](https://github.com/aave-dao/aave-v3-origin/tree/8305565ae342f1773c42cd2e4593f175fe5968a0): `src/contracts/protocol/pool/Pool.sol` (`getReserveData`) and `src/contracts/helpers/AaveProtocolDataProvider.sol` (`getReserveTokensAddresses`). ## Remaining boundaries

- Morpho position queries read **stored** market totals; pending interest is accrued by the contract on a later write. Correct virtual-share rounding does not turn that snapshot into a guaranteed current repayment quote. Configurable buffers and execution simulation remain necessary; long inactivity/high accrued interest can exceed a static buffer. No pending-interest accrual implementation was added in this patch.
- Multiple outstanding CoW orders can use the same wrapper-derived EVC namespace/current nonce before any settlement. The executor does not reserve nonces across submitted orders, and this review does not claim multiple such orders can all settle. The live wrapper implementation and deployed code hashes were not independently established, so ABI compatibility is not asserted as a contract proof.
- Authorization state can change between a read/signature and execution. Aave delegation and Morpho standing authorization may persist when an application does not execute the available revocation; users and applications must apply their intended cleanup policy. This patch does not change that API policy.
- State-override storage layouts used for migration simulation were inspected in SDK code but not validated against every deployed Aave, Morpho, or MetaMorpho implementation. No full fork matrix, smart-wallet matrix, rebasing/fee-on-transfer token matrix, solver/network adversarial test, or MetaMorpho deployment-bytecode equivalence check was run.
- Quote validation binds SDK-visible identity and final conditions; it does not independently establish fair market pricing or prove every generic swap payload. Source-verified contract checks and backend metadata are separate trust boundaries.
- The earlier TLA+ executor model is finite and concerns materialized execution. It does not model CoW settlement or all protocol migrations. These review regressions do not extend its theorem scope.

## Additional rewards and intrinsic APY integration sweep

The bounded extension reviewed the direct and V3 reward adapters, public reward types, viewer eligibility, claim planning and reward merging, and the intrinsic APY V3 adapter/service. Coverage now includes these paths; it remains a source review with focused regressions rather than live provider/contract certification.

Four additional issues were reproduced and corrected:

1. **Direct Merkl adapter disagreed with its claim planner on chain-specific distributors.** Default direct rewards stamped the standard distributor on chains 50 and 324, while the service correctly expected its existing chain overrides and refused those same rows. The address resolution is now shared in `rewardsService/merklDistributor.ts`. A direct fetch through claim planning checks Ethereum, chains 50 and 324, and an explicit custom distributor on all three. Unknown default deployment chains remain rejected by claim planning; the read path can return a reward without a claimed trusted target.
2. **Intrinsic APY overrides could silently truncate results.** Configuring pageSize=200 returned only 100 of 150 rows when the endpoint clamped requests to 100. Filtered asset batches above the cap likewise read only one page. The adapter now bounds page/asset counts to 100 and paginates filtered and full-chain reads; it follows echoed limits and explicit continuation flags and stops when the reported total is reached. Tests also use an endpoint cap of 20 for 45 assets. Pinned Data V3 echoes its limit. A custom short response supplying only total, without limit or hasMore, still stops early; general custom-response completeness is not established.
3. **V3 rewards could repeatedly request an unpaginated endpoint.** `/v3/apys/rewards` returns the complete list without pagination metadata. Both SDK reward-map and campaign-metadata readers used `rows.length >= 100` as a continuation signal; a 100-row response therefore repeated until a request failed or indefinitely if all requests succeeded. A bounded regression throws on the second request and failed before the correction. Missing pagination metadata now means a complete response, while explicit `hasMore`, `total`, or `limit` still supports custom paginated adapters. The regression also confirms metadata enrichment completes with one request and preserves token decimals.

4. **Direct rewards invented token precision when metadata was missing.** Brevis and legacy Fuul rows, and Fuul claimable rows without currency_decimals, assigned 18 despite the public UserRewardToken contract requiring unresolved decimals to stay absent. They now omit unresolved precision, retain supplied Fuul metadata (including 0 decimals), and keep a later resolved scale when aggregating same-token rows. Raw claim amounts remain unchanged. The synthetic regression covers each path and supplied scales 0, 6, and 18. An incorrect displayed amount for an actual non-18 token is a conditional consequence; no live wrong payout is claimed.

The first three named regressions failed before the Merkl/intrinsic fixes, the separate unpaginated-rewards regression failed before its correction, and the unresolved-decimals regression failed with 18 rather than undefined. `test/rewardsApyIntegration.test.ts` contains six named tests including explicit-pagination compatibility. These changes do not alter how provider Merkle proofs or signatures are verified on-chain.

API evidence: the fetched OpenAPI snapshot at `/private/tmp/euler-sdk-integration-review/openapi.json` has SHA-256 `eb30fc696a5d90a15b1ca8ce0786abdf82480b423eb4cc418eeb64988279a8d9`. Relevant entries are `/v3/apys/intrinsic`, `/v3/apys/rewards`, `/v3/rewards/breakdown`, `IntrinsicApy`, `RewardsApy`, `RewardBreakdown`, `PaginationMeta`, and `LimitParam`. Intrinsic APYs are percentage points, reward APR contributions are public percentages converted by the SDK into fractions, intrinsic rows are unique per chain/asset, and the shared request cap is 100. The current shape is tested, not every historical API deployment.

The unpaginated rewards behavior was also checked in the separate clean local data-v3 checkout at commit `fc9485fe2d7a38028871c59f2540118fe2a5c691`: `src/interface/http/routes/apys.ts` calls `successResponse` with only chain metadata for `/rewards`, and `src/interface/http/utils/response.ts` adds pagination fields only when explicitly supplied. That checkout was read without changing it; this is source-level evidence, not a claim that its commit is every live server's deployed revision.

Viewer eligibility continues to use normalized whitelist membership before blacklist membership, with an absent viewer representing a headline APR. Token-holding requirements and incomplete eligibility metadata are disclosed, not independently verified against user histories by that predicate. Existing V3 unknown-token handling retains unresolved decimals and raw amounts. Live third-party claim ABI/deployment verification and fully adversarial provider payload validation remain outside this extension.

Final rewards/APY validation: **102 tests across 3 files** (`rewardsApyIntegration.test.ts`, `rewardsService.test.ts`, `pluginIntegrationRegression.test.ts`) pass, as does the separate TypeScript check. The existing rewards tests use temporary localhost HTTP fixtures and some retain real provider requests. One run hit the unchanged Turtle test's default 5-second network deadline (101 passed, 1 timeout); the final run used `--testTimeout=30000` and passed all 102. Together with the swap/migration focused run above, these are scoped integration regressions; the root review records the overall SDK suite separately.
